# V05 solver status policy and validation

## Version boundary

The 510 primary terminals were generated by the archived historical code. That
code and its runner identities remain unchanged in `src/frozen/`. The correction
is supplied in `src/validated/common/`, with `scripts/prepare_validated_run.py`
as the recommended launcher for new runs. `scripts/prepare_run.py` is retained
only for explicitly requested historical reconstruction; it retains the known
historical status-handling behavior.

## Outcome contract

| HiGHS execution and model evidence | V05 action |
|---|---|
| Successful execution and optimal model, with a solution | Return the solution and keep the next lexicographic stage |
| Successful execution and proven infeasibility at the first stage | Return the infeasible oracle result |
| Time/iteration/solution limit, unknown, interrupt, ambiguous or other nonoptimal model status | Raise SolverUnresolvedError |
| Warning or error from HiGHS run, including a stale optimal/infeasible model status | Raise SolverUnresolvedError |
| Missing solution with an optimal status | Reject at the oracle boundary |
| Infeasibility after a completed optimal stage | Reject as inconsistent; do not classify the original oracle as infeasible |

Worker exceptions propagate through the archived runner's ERROR channel. Such a
run is not exact, and the unresolved task is not counted as an infeasible DONE.
Floating-point solution quality remains subject to the manuscript's numerical
conditions; status checks are not rational-arithmetic certificates.

## Reproduce the limited software validation

Use the pinned solver requirements. Pure status tests do not optimize:

```bash
python scripts/validate_software.py --out validation_status_only
```

The opt-in limited regression suite actually executes eight small cells and
two injected worker-failure checks, with a 90-second safety timeout per check:

```bash
python scripts/validate_software.py --out validation_small_cases --smoke
```

Linux affinity support and at least three allowed CPUs are required for the
two-worker checks. The outputs are placed in a new directory. They never enter
the primary data tables automatically. Historical inputs/references are fixed,
and no reference fronts are regenerated. See `qa/software_validation/` for the
checks actually performed for V05, including unit logs and per-cell raw outputs.

The 99 scenario count includes subcases within ten unit-test methods. It is not
a count of independently solved benchmark problems. The eight real small runs
cover three distinct instances and 2,593 MILP calls. Two injected worker runs
execute no optimization calls. HiGHS random-seed defaults are not invented or
retrospectively assigned; the correction does not change historical seed policy.
